## Reading the entries

Shared parser rules:

- **U32:** rejects values above `4_294_967_295`; accepts zero at parsing. Startup checks may subsequently reject zero.
- **MS:** rejects values above `18_446_744_073_709` milliseconds, because multiplication by `1_000_000` must fit `u64`; accepts zero at service parsing (`S/limits/names.rs:4`).
- **U64:** accepts every representable `u64`; the document reader rejects larger integers (`S/startup/application.rs:190`).
- **Setup-MS:** rejects zero and values above `18_446_744_073_709` (`SU/limits.rs:130`, `SU/limits.rs:143`).
- **Box-U32:** all box values, durations included, must fit `u32`; zero is accepted by `apply` (`B/limits.rs:85`).

All owning memory calculations use checked arithmetic and can refuse startup on overflow or an unrepresentable footprint. References below identify the substantive cross-limit checks; “none beyond sizing” means no additional relationship found.

## `forge_component.`

- **FC-positive:** every component scalar is positive, including durations and TLS fields; TLS ciphertext retention has its stronger minimum (`FC/limits.rs:301`, `FC/limits.rs:349`; `TLS/client/limits.rs:129`).

## Overrides with no runtime effect

Two fields have no runtime consumer in the surveyed revision:

1. **`forge.facts`**: parser assignment (`S/limits/names.rs:86`), profile (`S/limits.rs:173`), declaration (`F/limits.rs:36`), and hypothetical heap contribution (`F/limits.rs:222`). The actual forge constructor creates no queue from it (`F/domain.rs:545`). The real client fact queue uses **`forge.client.facts`** (`SC/domain.rs:91`).
2. **`forges.log_origins`**: parser/profile/declaration and startup comparisons only (`S/limits/names.rs:191`; `S/limits.rs:330`; `S/limits.rs:80`; `S/startup/checks.rs:1067`, `S/startup/checks.rs:1082`). Runtime component settings always receive `List::with_capacity(0)` for origins (`S/forge.rs:96`). Changing this override can change startup acceptance, but cannot admit a redirect origin.

Other bounds are intentionally consumed at startup rather than checked repeatedly: bundle files/bytes, configured sign-in members/endpoints/secret, and legacy setup org-list admission. They change the admitted retained configuration or data, so they are not equivalent to the two unused runtime fields above. Box restart/log/tail overrides affect `temper box`; plain `temper serve` checks them but only uses `box.line_bytes` (`CFG:602`; `T/setup.rs:111`; `T/lib.rs:501`).
