## Also: the settings’ document defaults

The four members are not an enforced all-four-or-none group at this HEAD.

- **None present:** temper selects `Defaults::Passed`, builds stock/application defaults from the configured LLM catalogue, and passes them to jig. `TS/startup.rs:389`, `TS/startup.rs:402`, `JC/defaults.rs:11`.
- **Any present:** temper selects `Defaults::Document`; supplied stock/application defaults are ignored. In this mode, `charters`, `templates` and `rules` are required, but **`policies` remains optional**, defaulting to `[]`. Thus the three required members without `policies` are accepted. `TS/startup.rs:390`, `JC/defaults.rs:74`, `JC/lib.rs:123`, `JC/projects.rs:35`.
- **A partial group missing required members:** ordinary missing-member diagnostics are emitted, not one special group refusal. For example, with valid `charters` present but the other three absent, the missing-member lines are exactly:
  ```text
  engine.templates: missing
  engine.rules: missing
  ```
  With only `policies` present, they are:
  ```text
  engine.charters: missing
  engine.templates: missing
  engine.rules: missing
  ```
  These follow the required lookups and temper’s exact `Missing` wording. `JC/defaults.rs:75`, `JC/defaults.rs:85`, `JC/lib.rs:125`, `JC/read.rs:70`, `TS/startup/problems.rs:160`.
- **Different direct-jig API mode:** explicitly calling jig’s decoder with `Defaults::Passed` refuses any of the four when present. Temper renders that refusal as **“engine.MEMBER: settings live in the store; read them with temper ctl DIR settings show”**. Normal temper startup’s selector instead switches to document mode. `JC/defaults.rs:66`, `TS/tests/stock.rs:131`, `TS/startup.rs:390`.

On the first empty-store start, the core validates defaults, saves each default, saves revision 1 with `FirstStart`, and saves the history extent. `JK/settings.rs:188`, `JK/settings/restart.rs:560`.

On a later start, it compares supplied defaults with the last stored defaults, restores owner changes, and stages changed/added/removed defaults. A change that affects an effective value produces a release revision after holders are restored. A default hidden by an owner change can be updated without changing that effective value. `JK/settings/restart.rs:92`, `JK/settings/restart.rs:247`, `JK/settings/restart.rs:366`, `JK/settings/restart.rs:447`.

A stored set or explicit removal wins over its default. Reset removes that overlay and follows the newest default. Defaults and the effective overlaid set are both checked. `JK/settings.rs:200`, `JK/settings/check.rs:57`, `JK/settings/check.rs:10`.

Retained task revisions and charter versions are preflighted before the release commit. A refusal sends no release writes. `JK/settings/restart.rs:426`, `JK/settings/restart.rs:439`. Named settings failures render as:

```text
settings.binary's default.KIND[N].FAULT: invalid form
settings.owner's stored change.KIND[N].FAULT: invalid form
```

Rules omit `[N]`; `FAULT` is `shape`, `count`, `reference`, `rules`, `budget`, `grace` or `owner`. The label “binary’s default” is also used when the supplied default originated in the document. `TS/stop.rs:185`, `TS/startup/problems.rs:164`.

## Also: document forms versus settings-file forms

Each line states the configuration-document form first, then the requested settings-fields form. Nested differences apply wherever those shapes occur.

- **Charter:** `instructions` is a config-relative file path → literal instruction text; `waiting_ms`, `time_ms`, `reserve_time_ms`, `call_timeout_ms` in milliseconds → `waiting`, `time`, `reserve_time`, `call_timeout` in nanoseconds; `model`/`alternatives` are catalogue-name strings → complete model objects. Document decoding copies the configured model records. `JC/charters.rs:73`, `JC/charters.rs:120`, `JC/charters.rs:148`; `SF:35`, `SF:36`, `SF:39`, `SF:41`, `SF:42`, `SF:48`, `SF:52`.
- **Template:** plain `name` → `{bytes,cut:false}`; nullable `tracked:{priority:N}` → nullable integer; flat `conversation`, `listed`, `retention`, optional `ended_by` → `flags`; `grace_ms` → nanosecond `grace`; deadline `{span_ms:N}` → `{span:N}` in nanoseconds; budget `{as_allowed:N|null}` → `{as_allowed:{cap:N|null}}`; LLM `sub_agents` → `subagents`, with an additional nullable `account`; the document does not accept approval contracts, verdict `cut`, or hex verdict-field names, whereas the settings form does. `JC/templates.rs:109`, `JC/templates.rs:136`, `JC/templates.rs:140`, `JC/templates.rs:234`, `JC/templates.rs:256`, `JC/templates.rs:285`, `JC/templates.rs:307`, `JC/templates.rs:428`, `JC/templates.rs:494`; `SF:75`, `SF:81`, `SF:82`, `SF:84`, `SF:98`, `SF:142`, `SF:155`, `SF:173`, `SF:185`, `SF:204`.
- **Policy:** document entries wrap `{number,policy,roles}`, where outer `roles` holds permission mappings and inner `policy.roles` holds authority roles → the settings item carries the number separately and its policy value contains `permissions` plus authority `roles`; template overrides remain inside the policy, subject to the nested budget/deadline differences above. `JC/projects.rs:49`, `JC/projects.rs:188`, `JC/projects.rs:224`; `SF:23`, `SF:215`, `SF:225`, `SF:238`.
- **Rules:** no direct member-name/unit/form difference: both have `ceiling`, `period_spend`, `minimum_run_spend`, `maximum_run_spend`, `implies`, `requirements`; authority, grant/pattern and requirement differences recurse into them. `JC/projects.rs:85`; `SF:256`.
- **Authority:** nested `budget:{spend,deadline_unix_seconds}` → flat `spend` and nullable `deadline` in Unix nanoseconds; omitted `models` means all and a present value is a list of plain model names → `"all"` or `{named:[HEX_NAMES]}`; delegation kinds `{kind,number}` → `{charter:N}`, `{procedure:N}` or `{role:N}`. `JC/projects.rs:317`, `JC/projects.rs:344`, `JC/projects.rs:395`, `JC/projects.rs:428`; `SF:275`, `SF:283`, `SF:288`, `SF:325`.
- **Grant:** no direct difference in `connector`, `kind`, `pattern`; its nested pattern changes form and byte representation as below. `JC/projects.rs:462`; `SF:295`.
- **Pattern:** plain-text `segments` plus `last:"exact"|"open"` and sibling `value:TEXT` → hex `segments` plus `last:{exact:HEX}` or `last:{open:HEX}`, with no sibling `value`. `JC/projects.rs:520`; `SF:303`, `SF:310`.
- **Requirement:** document `guard:"observed"` plus sibling `freshness_ms` → `guard:{observed:{freshness:NS}}`; `"guarded"` stays a string and forbids document `freshness_ms`. Connector, kind, judge and `must_be_guarded` retain their direct forms; pattern changes recurse. `JC/projects.rs:609`, `JC/projects.rs:619`; `SF:340`, `SF:359`, `SF:366`.
- **Role:** no direct difference: `number`, `authority`, `period_spend`, u16 `requests`, u8 `decides`; the authority differences above recurse. Permission mappings called outer `roles` in document project/policy entries are a separate shape, called `permissions` in the settings policy value. `JC/projects.rs:258`, `JC/projects.rs:284`; `SF:228`, `SF:248`.
