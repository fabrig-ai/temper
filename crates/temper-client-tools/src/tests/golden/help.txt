Agent tools

A box from nothing
Install temper (its build needs the wasm32-unknown-unknown target); temper help box has the walk.
  temper box --config C --data D --cache K
An empty C runs temper init first. Keep the box's terminal and pass its sign-in link on stdin.
DIRECTORY is ctl's private sign-in and request directory; reuse it for the calls below.
  temper ctl DIRECTORY sign-in -
  temper ctl DIRECTORY forge-setup 3 --org work --repository hello --project 1
  temper ctl DIRECTORY import FILE --key box-model-in
  temper ctl DIRECTORY wait accounts --until usable
  temper ctl DIRECTORY chat --project 1 TEXT --key box-change
  temper ctl DIRECTORY wait task 1 --until replied
  temper ctl DIRECTORY task 1 --tree
  temper ctl DIRECTORY wait change 2 --until landed
  temper ctl DIRECTORY change 2
  temper ctl DIRECTORY export 1 FILE
Setup prints the adoption and project; use that project, the chat's task and its delegated change's numbers.
Replace TEXT with one quoted request for a change in work/hello, or - to read it from stdin.
Instead of import, use connect 1 --key box-login and finish its printed sign-in link, or add-key below.
A host without a browser imports a login exported elsewhere or adds a private key file.
A refreshing login has one holder at a time. Export its granted sign_in account to a new private FILE
before Ctrl-C or SIGTERM stops the box; import removes the spent FILE. Keep C, D and K to resume.
The forge's diff, reviews, CI runs and logs, and branches are read on the forge with your chosen tools,
at the ids and links ctl prints. What temper owns there, its branches, pull requests and landing,
changes only through temper.

Read your party, projects, bounds and request retention:
  temper ctl DIRECTORY me
Wait, read what needs you, copy an act and its revisions, then act:
  temper ctl DIRECTORY wait me --until waiting
  temper ctl DIRECTORY inbox
  temper ctl DIRECTORY task 41 --tree
  temper ctl DIRECTORY message 41 investigating --key investigate-41
Loop by waiting again; use the matching read's digest with --since to wait for a change.
With --since and --until, both must hold. Read acts and their effects before sending.
A stopping engine's wait continues through reconnect and fails only past the link deadline.

Read deployment settings, then read a whole value as JSON, put its value member
in an items FILE, and edit it before one keyed decision:
  temper ctl DIRECTORY settings
  temper ctl DIRECTORY setting charter 3 --json
  temper ctl DIRECTORY change-settings FILE --against 5 --key settings-5
  temper ctl DIRECTORY propose-settings FILE --against 5 --key proposal-5
  temper ctl DIRECTORY proposal p3/7
Use setting ... --json > FILE to save a value; FILE for change-settings is
{"items":[{"setting":{"kind":"charter","number":3},"set":VALUE}]}.
Running work stays unless --running moves. On stale, read settings again and retry.
Agent task reads print settings: revision R, the revision recorded by the task.
A different live run adds its run on N; a different newest adds newest N.
Procedure and person tasks have no settings line. Task --json carries these numbers.

Read accounts without values; model names and limits are supplied facts:
  temper ctl DIRECTORY accounts
  temper ctl DIRECTORY models --project shop
  temper ctl DIRECTORY wait accounts --until usable
models has its own joined digest; wait accounts uses the accounts read's digest.
Settled follows party-requested sign-ins; program checks and provider readiness await upstream facts.
  temper ctl DIRECTORY connect 1 --key connect-llm
  temper ctl DIRECTORY add-key 1 FILE --deployment --key add-llm
  temper ctl DIRECTORY replace-key 43 FILE --key replace-llm
  temper ctl DIRECTORY declare 1 claude_code claude-work --key declare-llm
  temper ctl DIRECTORY verify 43 --source program
ADAPTER must appear in the provider's programs in me; the declare request carries no adapter binding.
NAME is 1 to 32 lower-case letters, digits or hyphens.
declare prints temper program-login NAME to run on each host; the tools never run it.
verify accepts only a program source, answers once asked, then prints wait accounts --until settled.
Move a signed-in account between deployments:
  temper ctl DIRECTORY export 43 FILE
  temper ctl DIRECTORY import FILE --key move-in
export creates FILE new and private before sending, writes and syncs the record, then sends written.
It takes no --key. Until written, failures remove FILE; lost exports can be tried again after the move's deadline.
After written, FILE is kept unless the engine refuses cancelled. A later call resends a kept written.
import reads a private owned regular file, never a link: 1 to 131072 bytes whole, with no newline trimmed.
A newer JIGM form requires upgrading temper before sending. Other forms are the engine's to decide.
Moved in prints the account and removes FILE; a failed removal exits 1 and says its record is spent.
Refused or lost imports keep FILE: ask again with the same --key and FILE. No record is printed or stored.
Keys use private files, never stdin or arguments; 1 to 4096 bytes after stripping one final newline.
Value requests are sent once, never kept or automatically replayed. Unsent/lost exits 1;
rerun with the same --key and file to recover the original answer. Only engine refusals exit 2.
disconnect, forget, rank and retry resolve a unique --source sign_in|key|program from accounts.
forget without --source removes the whole account; rank without it moves the account.
connect prints a browser address and wait accounts --until settled, then exits once durable.

Connect an existing GitHub App with its private PEM file:
  temper ctl DIRECTORY forge-connect 2 github-app 4242 FILE --key app-2
  temper ctl DIRECTORY wait forges --until connected:2
For a shared App, set forge 2's app_read_only to true in C/temper.json before starting the box.
Its hook is read and left; an unaccepted installation is kept, never uninstalled; the key and grants are checked.
The private file must be regular, owned by you, with no group or other permissions.
PEM is 1 to 4090 bytes after one final newline; the carried bundle is at most 4096 bytes.
It is sent once, never kept or replayed; use the same --key and file to recover a lost answer.
Read the connected App's installations, then accept one already made, with no browser:
  temper ctl DIRECTORY forges
  temper ctl DIRECTORY forge-accept 2 1
  temper ctl DIRECTORY repositories 2 --installation 1 --page 1
  temper ctl DIRECTORY adopt --project 1 --forge 2 --owner OWNER --name NAME --landing main --key github-adopt
Use the installation id from forges and the owner/name from repositories.
An unaccepted installation says not accepted; read-only mode says kept: the App is read-only.
Without read-only, reconcile uninstalls a stray once older than an installation link's lifetime: accept it first.
Or install on another account by opening the printed address on the engine's machine:
  temper ctl DIRECTORY forge-install 2
  temper ctl DIRECTORY wait forges --until settled
The tools print links; they never open a browser. A stopped install prints connecting and exits 1.

Start the built-in playground, or finish a previous failed start:
  temper ctl DIRECTORY demo-start --key playground
It waits for running; not offered exits 2, a start failure exits 1 and names why.

Choose a chat's main model from models --project P; --effort is required when that model declares efforts:
  temper ctl DIRECTORY chat --project shop --model chosen-model --effort chosen-effort hello --key model-chat
  temper ctl DIRECTORY amend 41 --rev 7 --model chosen-model --effort chosen-effort because --key model-amend
amend replaces each named control and keeps the rest; --rev names the shown spec revision.
Goal model flags arrive with area 2's goal tool and its executor/budget/deadline inputs.
Without these flags the template's choice or engine default is sent unchanged.
A model change preserves the supplied account and sub-agent choices; there is no --account flag.
Unknown model or effort names fail locally (exit 1), without sending.

Name keys for chat, message, close, adopt, connect, add-key, declare, import, change-settings and forge-connect; export takes no --key and other acts accept an optional --key NAME.
Names are one to 64 lower-case letters, digits or hyphens.
Give each agent a distinct prefix, such as investigate-41; reads and waits need no key.
A repeat keeps its name, party and ask within retention. A changed template or bound in me
can make another ask: the engine then answers a key conflict. Never reuse a name for new work.
TEXT is an argument or - for stdin, used only once.
--call FILE|- reads one JSON call; TEXT - is forbidden under --call -.
--json gives one object in snake case; help TOOL --json gives its table record.

Exit statuses:
0: a read answered, an act done or proposed, or a wait met. A sized too-large turn stays
   exit 0; report it as a finding and read smaller parts where offered.
1: usage or client failure, including limits, Held, NotKept and unknown past retention.
   Held may name another party's parked request; it is a client failure.
2: an engine refusal alone, including an engine key conflict.
3: an unmet wait's timeout or watch end. A signal's status is the OS's, never 0.
Unconfirmed or a client-side key conflict is a tools bug (exit 1); report it as a finding.

Recovery notices go on stderr, for example:
kept: create done: task 41, chat
A kept JSON notice has only operation and outcome, one object per stderr line, never a request name or key.
pending reads only the store, with no lock, client or send. Each row gives operation,
party N and first sending in wall-time words, or not sent. For example:
chat, party 3, not sent
JSON: {"pending":[{"operation":"chat","party":3,"first_sent":null}],"unread":2}
2 kept records these tools cannot read; a call that sends drops them
Unsupported store versions or undeclared family owners/versions are counted, never listed (exit 0).
An invalid store fails: DIRECTORY's store cannot be read (exit 1).
A sending call reports dropped and parked work on stderr, then goes on:
dropped: 2 kept records these tools cannot read
JSON: {"dropped":2}
kept: 2 for party 3, unsent while it is not signed in here
JSON: {"party":3,"unsent":2}
It answers and erases only the signed-in party's kept requests; other parties' work stays parked.

After a chat asks for a change, follow its change task through landing:
  temper ctl DIRECTORY wait change 2 --until landed
  temper ctl DIRECTORY change 2
The panel names its pull request, CI at its head, step, holds and merge commit.
Use change N --json for whole named facts and its digest; --project defaults to task N's project.
Change temper's branches, pull requests and their landing only through temper.
A part served there says: Shown on the forge.

Tools:
me
  Read the party, projects and waiting counts
inbox [--project P] [--kind K] [--root N] [--after C]
  Read what needs the party and its updates
tasks --project P [--label chat|goal] [--tracked] [--mine] [--ended] [--order activity|priority] [--after C] [--parent N]
  Read task lines
task N [--tree] [--activity K] [--run]
  Read a task and selected related documents
chat N [--before C]
  Read a conversation from its end
activity N [--before C] [--limit K]
  Read task activity from its end
turn N A.T [--part K] [--from B]
  Read one turn and its parts
run N
  Read a task's live run
chat --project P TEXT [--model M] [--effort E] --key NAME
  Start a chat
message N TEXT --key NAME
  Send words to a task
close N [--move D]... [--reason TEXT] --key NAME
  Close a chat and cancel or move its delegates
answer N M TEXT [--key NAME]
  Answer a task's question
decide tN/K|pN/K accept|reject|pass-up [REASON] [--running stays|moves] [--key NAME]
decide N --hold R release|leave|pass-up [REASON] [--key NAME]
  Decide a proposal or an escalation
release N --hold R [--again] [--key NAME]
  Lift a task's hold
stop N [--key NAME]
  Stop a task's run and hold it
cancel N [--grace D] REASON [--key NAME]
  Cancel a task and its tree
wait SUBJECT [--since DIGEST] [--until CONDITION] [--timeout DURATION]
wait forges [--since DIGEST] [--until settled|connected:F|made:F] [--timeout DURATION]
wait change N [--project P] [--since DIGEST] [--until pull|ci:pending|ci:passed|ci:failed|held|landed] [--timeout DURATION]
  Wait for a subject's change or condition
adopt --project P [--forge F] --owner O --name N --landing B [--role owned|fork|context] [--prefix X] [--no-home] [--no-ci] [--check G]... --key NAME
  Adopt a repository
sign-in FILE|-
  Sign in with the link the engine's host printed
sign-out
  End sign-in and leave the token empty
pending
  List requests kept in the store
help [TOOL]
  Read the guide or one tool's record
accounts
  Read accounts and their sources without values
models [--project P]
  Read authorized models grouped by provider
connect PROVIDER --key NAME
  Start an LLM provider sign-in
disconnect ACCOUNT [--source sign_in|key|program] [--key NAME]
  Sign an account source out
add-key PROVIDER FILE [--account A] [--deployment] --key NAME
  Add a key from a private file
replace-key ACCOUNT FILE [--key NAME]
  Replace an account's key from a private file
forget ACCOUNT [--source sign_in|key|program] [--key NAME]
  Remove an account or one source
rank ACCOUNT POSITION [--source sign_in|key|program] [--key NAME]
  Move an account or source to a one-based position
retry ACCOUNT [--source sign_in|key|program] [--key NAME]
  Resume a limited source
amend N [--rev R] [--priority P | --untracked] [--deadline T | --no-deadline] [--instructions FILE] [--spec FILE] [--dependency M]... [--no-dependencies] [--model M [--effort E]] REASON [--key NAME]
  Amend a task: each change named, the rest kept
declare PROVIDER ADAPTER NAME [--account A] --key NAME
  Declare a program login; the answer names the command for each host
verify ACCOUNT [--source sign_in|key|program] [--key NAME]
  Ask hosts to check a program login; then wait accounts --until settled
forges
  Read the deployment's forges
forge-setup F [--org O] [--repository R] [--project P] [--playground] [--key NAME]
  Set up an owned Forgejo here
demo-start [--key NAME]
  Start the playground; run again to finish what is not done
forge-connect F github-app ID FILE --key NAME
forge-connect F github --key NAME
forge-connect F forgejo FILE --key NAME
forge-connect F forgejo-admin FILE [--first ORG/NAME] [--project P] [--label L] --key NAME
  Connect GitHub or Forgejo as its admin
forge-install F [--key NAME]
  Print a fresh GitHub App installation link
repositories F [--installation I] [--page N]
  Read one page of reachable repositories
export ACCOUNT FILE
  Move a signed-in account out to a new private file, synced before written
import FILE --key NAME
  Move a record in from a private file, then remove the spent file
settings
  Read the settings, held revisions and pending proposals
setting charter|template|policy N [--revision R]
setting rules
  Read one setting's value whole; JSON values feed change-settings
revision R
  Read a revision and its whole items, or the oldest kept if forgotten
revisions [--before R]
  Read history newest first, a page at a time
change-settings FILE --against R [--running stays|moves] --key NAME
  Change deployment settings in one keyed decision
propose-settings FILE [REASON] --against R --key NAME
  Propose a change of deployment settings to its owners
proposal tN/K|pN/K
  Read a proposal, with its review for settings
change N [--project P]
  Read a change's way to landing: its pull request, CI and step
forge-accept F I [--key NAME]
  Accept an existing GitHub App installation
move-to-newest R --key NAME
  Move every live agent task on held revision R that may move to the newest
